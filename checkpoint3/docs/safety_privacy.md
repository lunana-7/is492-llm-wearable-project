# Speech, recognition and student control

Min owns this review. The classroom demo uses a trusted phone and laptop with consenting participants. The student chooses whether a follow-up is useful and sees exactly which roster entry will carry it.

| Stage | Implemented safeguard | Evidence or verification |
|---|---|---|
| Enroll | Explicit consent, a name and an embedding from exactly one face in the current enrollment photo. The storage call also checks consent. | Android instrumented test rejects enrollment without consent. On-device check: after a successful capture, open a blank or group photo and verify enrollment stays disabled. |
| Recognize | Local embeddings, provisional 0.60 threshold and three consecutive matches in the live path. Failed or interrupted observations clear the candidate streak and request a cleared card. | Roster test checks matched and orthogonal synthetic vectors. Actual false matches, lighting and lens latency require hardware evaluation. The still-photo preview has a separate single-match path. |
| Record | Each clip begins with explicit consent for the named profile and OS microphone permission. Eight seconds of phone PCM live in RAM. Dismissing the dialog during capture cancels it and releases the recorder. | Verify the visible recording state and cancellation on a phone. Permission and verbal consent from all speakers remain distinct. |
| Transcribe | Debug app sends WAV over USB-forwarded loopback. The service checks consent header, content type, length and PCM format before transcription. It rejects browser origins and processes one recording at a time. | HTTP tests cover denied consent, browser origin, malformed audio, busy service and retry. The header expresses the client’s consent decision; it does not authenticate a user. |
| Summarize | Local Qwen selects a short verbatim quote from Whisper’s transcript. Matching is checked in code. Email and common digit-based phone patterns are redacted before the model request. The service abstains on common explicit instruction-override phrases. The prompt marks the rest of the transcript as untrusted. | Unit tests reject invented content and contact details. The live test runs a synthetic clip through both actual models. Speech recognition errors, names, spoken numbers and misleading exact quotes still require human review. |
| Approve or discard | The selected student can edit, discard or explicitly save the draft. The app updates only the selected enrolled object. A deleted/re-enrolled profile rejects a stale draft. | Android tests check retrieval before and after approval, removal, deletion, and stale approval. |
| Retain and delete | The phone encrypts approved text with the existing roster using Android Keystore AES-GCM. Delete the note to restore the previous card or delete the entry to remove its embeddings and note. Android backup is disabled. | Check roster removal in the device test. Manually clear demo profiles at the end of the session. Term-end expiry and authenticated student self-service remain open. |

The speech service keeps audio, transcripts and unapproved drafts in process memory. Closing a dialog after upload discards the result on the phone; an in-flight laptop computation can finish. The app records no transcript in its roster. The existing camera capture/share and video features have their own storage paths. Exported media must be managed separately.

This demo assumes supervised access, distinct preferred names and a trusted local machine. The existing roster groups samples by name, so two people with the same name can share an entry. Use distinct synthetic identifiers for the demo. A classroom deployment needs unique student IDs, authenticated student approval, retention enforcement, separate review of legacy entries and empirical false-match testing before use.
